# ECO — مساحة العمل الهندسية

واجهة عربية RTL بسيطة باللون الأبيض والرمادي ولمسة ذهبية من اللوجو. تعمل كملفات ثابتة على GitHub Pages، بدون تثبيت مكتبات أو Backend للواجهة.

## تشغيل محلي

يُستخدم Node.js 22 أو أحدث:

```powershell
cd D:\ECO\ECO_Server
npm.cmd start
```

افتح `http://127.0.0.1:4173`. لإيقاف التشغيل اضغط Ctrl+C. لا تفتح `index.html` مباشرة بـ file:// لأن المشروع يستخدم JavaScript modules.

```powershell
npm.cmd run check
npm.cmd test
```

## الموجود في النسخة الأساسية

- صفحة رئيسية متجاوبة، اللوجو المرفق، وثلاث خدمات بأيقونات مستقلة.
- مساحة محادثة لكل خدمة، إرفاق ملفات، أمثلة لبدء الطلب، ومحادثات جديدة.
- حفظ نصوص المستخدم وردود الخدمة وأسماء المرفقات محليًا في `localStorage`، واسترجاعها بعد إعادة فتح المتصفح.
- سجل محادثات، تصدير JSON، وحذف بتأكيد.
- الإرسال يعرض حالة تجهيز صريحة إذا لم يُضف رابط workflow، ولا يختلق نتائج هندسية.
- موصل n8n منفصل لكل خدمة، مع المهلة ومعالجة أخطاء الاتصال.
- الدخول مفتوح الآن. نموذج اسم مستخدم وكلمة مرور مُجهز للتفعيل من الكود.

هذه نسخة هيكل وواجهة؛ لا تتضمن محرك حصر أو تحليل أسعار أو توليد رسومات. خاصية Listen مؤجلة. لا يوجد رفع ملفات عند اختيارها؛ يرسل محتواها إلى n8n فقط عند الإرسال وبعد ضبط الرابط. السجل يحتفظ **بأسماء الملفات وبياناتها الوصفية فقط** وليس محتواها؛ يجب إعادة إرفاق الملف في طلب جديد. الحد الأقصى 5 ملفات بإجمالي 12 MiB لكل طلب.

الحفظ محلي لكل browser profile وorigin. سجل localhost لا ينتقل تلقائيًا إلى عنوان GitHub، ومسح بيانات المتصفح يمسح المحادثات. التصدير نسخة احتياطية JSON؛ استيراد النسخ لم يُضف بعد. لا يُحفظ نص المسودة غير المرسلة بعد إعادة تحميل الصفحة. لا يوجد Service Worker حاليًا؛ فتح التطبيق لأول مرة يحتاج ملفات الموقع، أما تخزين السجل فلا يحتاج إنترنت.

## الملفات والتوسع

| الملف | الغرض |
| --- | --- |
| `js/config.js` | قائمة الخدمات، إعدادات كل workflow، وإعدادات واجهة الدخول |
| `js/app.js` | التنقل والصفحات والمحادثة |
| `js/workflow.js` | النقل إلى n8n وصيغة الرد والأخطاء |
| `js/storage.js` | تخزين المحادثات، نقطة استبدال مستقبلية بـ IndexedDB |
| `js/icons.js` | أيقونات SVG محلية |
| `styles.css` | الألوان والخط العربي والتصميم المتجاوب |
| `assets/` | اللوجو الأصلي والخط المحلي IBM Plex Sans Arabic وترخيصه |

لإضافة خدمة: أضف تعريفًا إلى `services` ومعرّفًا مطابقًا داخل `config.workflows` في `js/config.js`. ستظهر تلقائيًا في الكروت والقائمة وصفحة المحادثة، ويظل سجلها مستقلاً. يمكن إضافة أيقونة جديدة في `js/icons.js`.

## ربط n8n

هناك 3 إعدادات منفصلة في `js/config.js`:

```js
workflows: {
  review:  { url: '', timeoutMs: 120000 },
  takeoff: { url: '', timeoutMs: 120000 },
  design:  { url: '', timeoutMs: 120000 },
}
```

ضع **Production Webhook URL** بـ HTTPS في إعداد الخدمة المقابلة. كل workflow يبدأ بعقدة Webhook بطريقة POST، وينتهي برد نصي داخل JSON:

```json
{ "reply": "نتيجة المعالجة هنا" }
```

يدعم الموصل أيضًا `output` و`text`، وأول عنصر من مصفوفة n8n، أو رد `text/plain`. يعرض الرد كنص آمن، دون تشغيل HTML. تنزيل مخرجات DXF/PDF واستقبال تدفق الردود أو مهام طويلة الأجل مؤجل لمرحلة الربط الفعلي.

يُرسل `multipart/form-data`:

| الحقل | المحتوى |
| --- | --- |
| `sessionId` | معرّف المحادثة |
| `serviceId` | `review` أو `takeoff` أو `design` |
| `message` | الرسالة الحالية |
| `history` | JSON لرسائل user وassistant، شاملًا الرسالة الحالية، دون ملاحظات النظام المحلية |
| `files` | الملفات الفعلية المختارة للطلب الحالي، اسم حقل متكرر |

استخدم `Respond to Webhook` أو `When Last Node Finishes` لإرجاع النتيجة، واضبط CORS على أصل الموقع مثل `https://USERNAME.github.io` وأصل المعاينة أثناء التطوير. لا تستخدم `Immediately` إن أردت عرض نتيجة المعالجة نفسها. قد تحتاج تفعيل استقبال binary files بحسب إعداد workflow. حد n8n الافتراضي المذكور في الوثائق 16MB؛ حد المرفقات في الواجهة أقل لتوفير مساحة لباقي الطلب.

المهلة 120 ثانية قابلة للتعديل. لا نُعيد الطلب تلقائيًا لتجنب تنفيذ نفس المهمة مرتين؛ انتهاء مهلة المتصفح لا يعني توقف التنفيذ داخل n8n.

توثيق n8n الرسمي: [Webhook](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/).

## تسجيل الدخول

`config.auth.enabled` يساوي `false` الآن؛ لا تُطلب بيانات دخول. لتجربة بوابة دخول مرئية مستقبلًا، غيّره إلى `true` وأضف حسابات في `users` بصيغة `{ username, passwordSha256 }`. الدخول يستمر في ذاكرة الصفحة حتى إعادة تحميلها.

**حد تقني أساسي:** بوابة JavaScript على GitHub Pages قابلة للتجاوز. حتى تخزين hash في الكود لا يجعلها حماية حقيقية. لم تُضف أي كلمات مرور أو أسرار. عند الحاجة لحماية البيانات وتنفيذ workflows، يُضاف تحقق فعلي على خادم أو وسيط موثوق. روابط webhook الموجودة بالواجهة عامة؛ لا تضع API keys أو كلمات مرور n8n في الملفات العامة. CORS ليس بديلًا عن التحقق من الصلاحيات.

## النشر على GitHub Pages

المستودع: [Mohamedsamy125/ECO_Server](https://github.com/Mohamedsamy125/ECO_Server).

عنوان الموقع: [ECO](https://mohamedsamy125.github.io/ECO_Server/). يتوفر بعد اكتمال نشر GitHub Pages.

إعداد Actions موجود في `.github/workflows/pages.yml` ويُحدّث الموقع مع كل push إلى `main`:

1. ارفع ملفات المشروع إلى مستودع GitHub على فرع `main`.
2. من Settings → Pages اختر Source: **GitHub Actions**.
3. شغّل workflow `Deploy ECO to GitHub Pages` أو ادفع تغييرًا إلى `main`.
4. سينشر الملفات العامة فقط: `index.html` و`styles.css` و`js/` و`assets/`؛ ولا ينشر الاختبارات أو ملفات التطوير.

المسارات نسبية، فتعمل أيضًا على `https://USERNAME.github.io/REPOSITORY/`. لا تحتاج تثبيت dependencies أو build. يمكن بديلًا اختيار Deploy from a branch → main → root؛ سيتاح حينها أي ملف موجود في مصدر النشر.

التوثيق الرسمي: [إنشاء موقع GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)، [إعداد مصدر النشر](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).
